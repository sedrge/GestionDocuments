Chapitre 1Les fondations

Avant d'écrire une seule ligne de code, tu dois comprendre pourquoi React Native existe, ce qu'Expo y ajoute, et comment le projet SenMoto est organisé. Ce chapitre pose les bases mentales indispensables pour tout ce qui suit.

1.1 — Qu'est-ce que React Native ?

Quand tu veux créer une application mobile, tu as deux options classiques :

ApprocheDescriptionAvantagesInconvénients
Natif purSwift/Kotlin pour iOS/AndroidPerformances maximalesDeux codebases à maintenir
Hybride (WebView)HTML/CSS/JS affiché dans WebViewUn seul codeLent, look pas natif
React Native ✅JavaScript qui compile en composants natifsUn code → vrai natifQuelques limites de perf

React Native (créé par Meta en 2015) utilise JavaScript pour décrire votre interface, mais le moteur React Native traduit chaque composant en widget natif réel : un <View> devient un UIView sur iOS et un android.view.View sur Android.

💡 Concept clé : "Learn Once, Write Anywhere" Le slogan de React Native. Tu apprends un seul paradigme (React + composants) et tu cibles iOS, Android et même le Web avec le même code.

1.2 — Qu'est-ce qu'Expo ?

React Native seul est puissant mais complexe à configurer. Expo est un framework et une plateforme construits par-dessus React Native pour simplifier le développement.

Ce qu'Expo apporteSans ExpoAvec Expo
Démarrer un projetXcode + Android Studio requisnpx create-expo-app suffit
CaméraCode natif Swift/Kotlinexpo-camera
NotificationsFirebase/APNs manuellementexpo-notifications
BuildMachines macOS/Linux requisesEAS Build (cloud)
TestSimulateur ou vrai appareilExpo Go (app) ou Dev Build

SDK Expo 56 — Pourquoi ce numéro de version ?

Le SDK Expo suit un cycle de versions. Le projet SenMoto utilise SDK 56, qui correspond à React Native 0.85. Chaque bibliothèque Expo (expo-camera, expo-notifications, etc.) a une version compatible avec le SDK.

⚠️ Règle d'or des versions Toujours utiliser npx expo install nom-du-package au lieu de npm install pour les packages Expo. La commande choisit automatiquement la version compatible avec ton SDK.

1.5 — TypeScript dans React Native

SenMoto est écrit en TypeScript (fichiers .tsx et .ts). TypeScript ajoute des types à JavaScript pour détecter les erreurs avant l'exécution.

Syntaxe TypeScript utilisée dans le projet

// 1. Interface : définir la forme d'un objet
interface Moto {
  id: string;
  marque: string;
  prix_vente: number | null; // peut être null
  etat: 'Neuve' | 'Occasion';  // type union (enum)
  images?: MotoImage[];         // optionnel (le ? le dit)
}

// 2. Props d'un composant
interface MapPickerModalProps {
  visible: boolean;
  onClose: () => void;           // fonction sans retour
  onLocationSelected: (location: LocationResult) => void;
  initialLatitude?: number;      // paramètre optionnel
}

// 3. Type alias
type UserRole = 'super_admin' | 'enterprise_admin' | 'user';
type PendingState = 'enterprise_pending' | 'user_pending' | null;

// 4. Générique : fonction qui travaille sur n'importe quel type
const getFirst = <T>(items: T[]) : T | undefined => items[0];

// 5. useState avec type explicite
const [location, setLocation] = useState<LocationResult | null>(null);

tsconfig.json du projet

{
  "extends": "expo/tsconfig.base",   // Config Expo recommandée
  "compilerOptions": {
    "strict": true,                  // Mode strict (recommandé)
    "paths": {
      "@/*": ["."]                   // @/lib/... = ./lib/...
    }
  }
}
✅ L'alias @/ Dans tout le projet, @/lib/supabase pointe vers ./lib/supabase.js. C'est plus propre que des chemins relatifs ../../lib/supabase.

Chapitre 2Les composants de base

React Native ne dispose pas de <div>, <p> ou <button>. Il a ses propres composants primitifs qui se mappent aux éléments natifs iOS et Android. Ce chapitre couvre chaque primitif avec des exemples tirés de SenMoto.

2.1 — View, Text, Image, ScrollView

View — Le conteneur universel

View est l'équivalent de <div>. C'est un rectangle qui contient d'autres éléments. Il n'affiche rien par lui-même — il sert à structurer et styler. 

import { View, Text } from 'react-native';

// Exemple réel : en-tête du menu hamburger (HamburgerMenu.tsx)
function MenuHeader() {
  return (
    {/* View principale : colonne verticale */}
    <View style={{ flex: 1, backgroundColor: '#121212' }}>

      {/* View enfant : ligne horizontale */}
      <View style={{ flexDirection: 'row', padding: 16 }}>
        <Text style={{ color: '#fff' }}>SenMoto</Text>
      </View>

    </View>
  );
}

Text — Tout texte doit être dans Text

En React Native, tu ne peux pas mettre du texte directement dans une View. Il doit toujours être dans un composant Text.

// ❌ FAUX — Crash !
<View>Bonjour</View>

// ✅ CORRECT
<View>
  <Text>Bonjour</Text>
</View>

// Exemples de style de texte (admin/dashboard.tsx)
<Text style={{
  fontSize: 28,
  fontWeight: 'bold',
  color: '#FFFFFF',
  letterSpacing: 0.5,
}}>
  Tableau de bord
</Text>

// Texte tronqué (très utilisé dans les listes)
<Text numberOfLines={1} ellipsizeMode="tail">
  Nom très long qui sera tronqué avec ...
</Text>

Image — Afficher une image

import { Image } from 'react-native';

// Image depuis l'internet
<Image
  source={{ uri: 'https://exemple.com/moto.jpg' }}
  style={{ width: 200, height: 150 }}
/>

// Image base64 (utilisé dans SenMoto pour les photos de motos)
<Image
  source={{ uri: 'data:image/jpeg;base64,/9j/4AAQ...' }}
  style={{ width: 300, height: 200, borderRadius: 12 }}
  resizeMode="cover"
/>

// Image locale (dans les assets)
<Image
  source={require('./assets/images/SenMoto.png')}
  style={{ width: 80, height: 80 }}
/>
📌 expo-image vs Image SenMoto utilise aussi expo-image (importé de 'expo-image'). C'est une version améliorée avec cache mémoire+disque, transitions animées, et meilleure performance. Préfère-la pour les listes avec beaucoup d'images.

ScrollView — Zone défilante

import { ScrollView } from 'react-native';

// Exemple : formulaire de création d'entreprise (create-enterprise.tsx)
return (
  <SafeAreaView style={{ flex: 1 }}>
    <ScrollView
      style={{ flex: 1 }}
      contentContainerStyle={{ padding: 20, paddingBottom: 40 }}

2.2 — StyleSheet et Flexbox

StyleSheet.create() — Définir les styles

import { StyleSheet, View, Text } from 'react-native';

export default function MaPage() {
  return (
    <View style={styles.container}>
      <Text style={styles.titre}>SenMoto</Text>
    </View>
  );
}

// Toujours définir les styles à la fin du fichier
const styles = StyleSheet.create({
  container: {
    flex: 1,                      // Prend tout l'espace disponible
    backgroundColor: '#121212',
    padding: 20,
  },
  titre: {
    fontSize: 28,
    fontWeight: 'bold',
    color: '#FFFFFF',
    marginBottom: 16,            // Espacement en bas (pas de px !)
  },
});
✅ Pourquoi StyleSheet.create() et pas des objets inline ? StyleSheet.create() optimise les styles (validation au démarrage, envoi natif une seule fois). Les objets inline style={{ color: 'red' }} recrées un objet à chaque rendu — moins efficace.

Flexbox — La mise en page en React Native

React Native utilise Flexbox par défaut pour tous les layouts. La différence avec le web : la direction par défaut est column (vertical) et non row. 

// Exemple concret : toolbar du MapPickerModal
const styles = StyleSheet.create({

    // Prend 1 part de l'espace

    backgroundColor: '#0A84FF',
    justifyContent: 'center',  // Centre le texte verticalement
    alignItems: 'center',       // Centre le texte horizontalement
  },

    // Prend 1.2 parts (un peu plus large)

2.5 — Listes : FlatList

FlatList est le composant pour afficher de longues listes efficacement. Il ne rend que les éléments visibles à l'écran (virtualisation). 

import { FlatList, View, Text } from 'react-native';

// Exemple : liste de motos dans le feed public (app/(tabs)/index.tsx)
type Moto = {
  id: string;
  marque: string;
  prix_vente: number | null;
};

function ListeMotos({ motos }: { motos: Moto[] }) {
  return (
    <FlatList<Moto>
      data={motos}                              // Tableau de données
      keyExtractor={(item) => item.id}          // Clé unique (obligatoire)
      renderItem={({ item }) => (               // Rendu de chaque élément
        <View style={styles.card}>
          <Text>{item.marque}</Text>
          <Text>{item.prix_vente?.toLocaleString()} FCFA</Text>
        </View>
      )}
      // Afficher un loader en bas pendant chargement
      ListFooterComponent={loading ? <ActivityIndicator /> : null}
      // Afficher quand la liste est vide
      ListEmptyComponent={
        <Text style={styles.empty}>Aucune moto disponible</Text>
      }
      // Charger plus quand l'utilisateur arrive en bas
      onEndReached={loadMore}
      onEndReachedThreshold={0.3}             // Déclenche à 30% avant la fin
      // Espacement entre items
      ItemSeparatorComponent={() => <View style={{ height: 12 }} />}
    />
  );
}

Chapitre 3React — Les Hooks essentiels

Les Hooks sont des fonctions spéciales de React qui permettent d'ajouter de la logique (état, effets, références) à des composants fonctionnels. SenMoto les utilise massivement — on va voir chacun avec son exemple concret du projet.

3.1 — useState : gérer l'état local

useState ajoute une variable qui, quand elle change, force le composant à se re-rendre. C'est la base de l'interactivité. 

import { useState } from 'react';

// Syntaxe : [valeur, setValeur] = useState(valeurInitiale)

// Exemple 1 : loading spinner (create-enterprise.tsx)
const [loading, setLoading] = useState(false);

const handleSubmit = async () => {
  setLoading(true);       // Affiche ActivityIndicator
  try {
    await createEnterprise(formData);
  } finally {
    setLoading(false);    // Cache ActivityIndicator
  }
};

// Exemple 2 : formulaire avec plusieurs champs
const [formData, setFormData] = useState({
  enterpriseName: '',
  adminEmail: '',
  adminPassword: '',
});

// Met à jour UN champ sans écraser les autres (spread ...)
const handleChange = (field: string, value: string) => {
  setFormData(prev => ({ ...prev, [field]: value }));
};

// Exemple 3 : liste de données
const [motos, setMotos] = useState<Moto[]>([]);

// Ajouter un élément à la liste
const addMoto = (moto: Moto) => {
  setMotos(prev => [...prev, moto]);
};
📌 Règle importante : ne jamais muter directement le state 
// ❌ Faux : mutation directe
motos.push(nouvelleMoto);       // React ne voit PAS le changement

// ✅ Correct : nouveau tableau
setMotos([...motos, nouvelleMoto]);  // React re-rend le composant

3.2 — useEffect : effets de bord

useEffect exécute du code après le rendu du composant. Utilisé pour : charger des données, s'abonner à des événements, configurer des timers. 

import { useState, useEffect } from 'react';

// Syntaxe : useEffect(fonction, [dépendances])

// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// Cas 1 : Charger données au montage (admin/users.tsx)
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
const [users, setUsers] = useState([]);

useEffect(() => {
  const fetchUsers = async () => {
    const data = await getActiveUsers(enterpriseId);
    setUsers(data);
  };
  fetchUsers();
}, []);  // [] = exécute UNE SEULE FOIS au montage

// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// Cas 2 : Réagir à un changement (notifications.tsx)
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
useEffect(() => {
  // Recharge les notifs quand l'ID change
  loadNotifications(userId);
}, [userId]);  // Exécute chaque fois que userId change

// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// Cas 3 : Nettoyage (lib/firebase.ts)
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
useEffect(() => {
  // S'abonner aux notifications
  const subscription = setupNotificationListeners();

  // Retourner une fonction de nettoyage
  return () => {
    subscription.remove();  // Désabonner quand composant démonté
  };
}, []);

// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// Cas 4 : Pas de dépendances = exécute à CHAQUE rendu
// (éviter généralement)

useRef crée une référence persistante entre les rendus qui ne déclenche PAS de re-rendu quand elle change. Utilisé pour : accéder à un élément DOM/natif, stocker une valeur mutable. 

import { useRef } from 'react';
import { WebView } from 'react-native-webview';

// Exemple réel : injecter du JavaScript dans la WebView (MapPickerModal.tsx)
function MapPickerModal() {

  const webViewRef = useRef<WebView>(null);

    // Accès direct au composant WebView sans re-rendre
    webViewRef.current?.injectJavaScript(
      `receiveLocation(${lat}, ${lng}); true;`
    );
  };

  return (
    <WebView
      ref={webViewRef}      // Attache la référence
      source={{ html: mapHtml }}
    />
  );
}

Chapitre 4Navigation avec Expo Router

Expo Router est le système de navigation de SenMoto. Il transforme automatiquement chaque fichier dans le dossier app/ en une route accessible. C'est la même philosophie que Next.js App Router, mais pour mobile.

4.1 — Principe du file-based routing

// La structure des fichiers DEVIENT la navigation :

app/
  _layout.tsx         → Layout racine (toujours chargé)
  home.tsx            → Route /home
  moto.tsx            → Route /moto
  auth/
    login.tsx         → Route /auth/login
  admin/
    dashboard.tsx     → Route /admin/dashboard
  (tabs)/
    index.tsx         → Route / (onglet 1)
    explore.tsx       → Route /explore (onglet 2)
📌 Parenthèses dans les noms de dossier (tabs) est un "route group" — les parenthèses disparaissent de l'URL. app/(tabs)/index.tsx correspond à la route /, pas /(tabs)/. C'est utile pour organiser les fichiers sans affecter les URLs.

4.2 — Layouts (_layout.tsx)

Un fichier _layout.tsx définit la structure commune de toutes les routes dans son dossier. Il reste monté pendant la navigation entre ses enfants. 

// app/_layout.tsx — Layout racine du projet SenMoto
import { Stack } from 'expo-router';

export default function RootLayout() {
  return (
    {/* Providers globaux */}
    <SafeAreaProvider>
      <ThemeProvider>
        <TenantProvider>
          {/* Stack = navigation en pile (une page par-dessus l'autre) */}
          <Stack>
            {/* Configurer l'affichage de chaque route */}

              name="home"
              options={{ headerShown: false }}  // Pas d'en-tête
            />
            <Stack.Screen
              name="auth/login"
              options={{ title: 'Connexion' }}
            />
          </Stack>
        </TenantProvider>
      </ThemeProvider>
    </SafeAreaProvider>
  );
}

4.5 — Route Guard : protection des routes

Dans SenMoto, les utilisateurs non connectés ne doivent pas accéder aux pages privées. Voici comment le RouteGuard est implémenté dans app/_layout.tsx : 

// Pattern : RouteGuard dans le RootLayout
function AppStack() {
  const { tenant, loading, isAuthenticated, pendingState,
          isSuperAdmin, isEnterpriseAdmin } = useTenant();
  const segments = useSegments(); // Chemin actuel ex: ['admin','dashboard']
  const router = useRouter();

  useEffect(() => {
    if (loading) return; // Attendre que le tenant soit chargé

    const inAuthGroup = segments[0] === 'auth';
    const inOnboarding = segments[0] === 'onboarding';
    const inAdmin = segments[0] === 'admin';

    if (!isAuthenticated && !inOnboarding && !inAuthGroup) {
      router.replace('/onboarding');
      return;
    }

    if (isAuthenticated && inAdmin && !isSuperAdmin && !isEnterpriseAdmin) {
      router.replace('/home'); // User normal essaie /admin → rediriger
    }
  }, [loading, isAuthenticated, segments, tenant]);

  return <Stack screenOptions={{ headerShown: false }} />;
}

Chapitre 5State global avec Context API

Quand plusieurs composants éloignés ont besoin des mêmes données (ex: l'entreprise connectée, le thème sombre/clair), passer les props à travers chaque niveau devient impossible. La Context API de React résout ce problème.

5.1 — Le problème du "prop drilling"

// ❌ Prop drilling : passer tenant à travers tous les niveaux
<RootLayout tenant={tenant}>
  <HomeScreen tenant={tenant}>
    <HamburgerMenu tenant={tenant}>
      <MenuItem tenant={tenant}>  // ← problème ici
        ...
      </MenuItem>
    </HamburgerMenu>
  </HomeScreen>
</RootLayout>

// ✅ Avec Context : accès direct depuis n'importe où

5.2 — TenantContext : qui est connecté ?

// context/TenantContext.tsx — Code complet annoté

import { createContext, useContext, useEffect, useState } from 'react';
import { supabase } from '@/lib/supabase';

// ━━━ 1. Types ━━━
export interface TenantInfo {
  enterprise_id: string;
  enterprise_name: string;
  enterprise_code: string;
  enterprise_logo_url: string | null;
  user_id: string;
  user_role: 'super_admin' | 'enterprise_admin' | 'user';
  is_enterprise_active: boolean;
  is_user_active: boolean;
}

export type PendingState =
  | 'enterprise_pending'  // L'entreprise attend validation super-admin
  | 'user_pending'        // L'user attend validation admin entreprise
  | 'no_enterprise'       // L'user n'appartient à aucune entreprise
  | null;

interface TenantContextType {
  tenant: TenantInfo | null;
  loading: boolean;
  isAuthenticated: boolean;
  pendingState: PendingState;
  refreshTenant: () => Promise<void>;
  isSuperAdmin: boolean;
  isEnterpriseAdmin: boolean;
  isRegularUser: boolean;
}

// ━━━ 2. Créer le Context (valeur par défaut) ━━━
const TenantContext = createContext<TenantContextType>({
  tenant: null,
  loading: true,
  isAuthenticated: false,
  pendingState: null,
  refreshTenant: async () => {},
  isSuperAdmin: false,
  isEnterpriseAdmin: false,
  isRegularUser: false,
});

// ━━━ 3. Le Provider : enveloppe l'application ━━━
export function TenantProvider({ children }: { children: React.ReactNode }) {
  const [tenant, setTenant] = useState<TenantInfo | null>(null);
  const [loading, setLoading] = useState(true);
  const [isAuthenticated, setIsAuthenticated] = useState(false);
  const [pendingState, setPendingState] = useState<PendingState>(null);

  const loadTenant = async () => {
    try {
      // Récupérer la session Supabase
      const { data: { session } } = await supabase.auth.getSession();

      if (!session) {
        setIsAuthenticated(false);
        setLoading(false);
        return;
      }

      setIsAuthenticated(true);
      const userId = session.user.id;

      // Étape 1 : Vérifier si super_admin
      const { data: superAdmin } = await supabase
        .from('super_admins')
        .select('user_id')
        .eq('user_id', userId)
        .single();

      if (superAdmin) {
        setTenant({
          enterprise_id: 'super',
          enterprise_name: 'Super Admin',
          enterprise_code: 'SUPER',
          enterprise_logo_url: null,
          user_id: userId,
          user_role: 'super_admin',
          is_enterprise_active: true,
          is_user_active: true,
        });
        return;
      }

      // Étape 2 : Vérifier enterprise_admins
      const { data: adminRecord } = await supabase
        .from('enterprise_admins')
        .select(`*, enterprises(*)`)
        .eq('user_id', userId)
        .single();

      if (adminRecord) {
        const enterprise = adminRecord.enterprises;
        if (!enterprise.is_active) {
          setPendingState('enterprise_pending');
          return;
        }
        setTenant({
          enterprise_id: enterprise.id,
          enterprise_name: enterprise.name,
          enterprise_code: enterprise.code,
          enterprise_logo_url: enterprise.logo_url,
          user_id: userId,
          user_role: 'enterprise_admin',
          is_enterprise_active: enterprise.is_active,
          is_user_active: adminRecord.is_active,
        });
        return;
      }

      // Étape 3 : Vérifier enterprise_users
      const { data: userRecord } = await supabase
        .from('enterprise_users')
        .select(`*, enterprises(*)`)
        .eq('user_id', userId)
        .single();

      if (userRecord) {
        if (!userRecord.is_active) {
          setPendingState('user_pending');
        } else {
          setTenant({ ...userRecord, user_role: 'user' });
        }
        return;
      }

      // Aucun rôle trouvé
      setPendingState('no_enterprise');

    } finally {
      setLoading(false);
    }
  };

  useEffect(() => {
    loadTenant();

    // Écouter les changements de session Supabase
    const { data: { subscription } } = supabase.auth.onAuthStateChange(
      (event) => {
        if (event === 'SIGNED_OUT') {
          setTenant(null);
          setIsAuthenticated(false);
        } else if (event === 'SIGNED_IN') {
          loadTenant();
        }
      }
    );

    return () => subscription.unsubscribe();
  }, []);

  // Valeurs calculées (dérivées du state)
  const isSuperAdmin = tenant?.user_role === 'super_admin';
  const isEnterpriseAdmin = tenant?.user_role === 'enterprise_admin';
  const isRegularUser = tenant?.user_role === 'user';

  return (
    <TenantContext.Provider value={{
      tenant, loading, isAuthenticated, pendingState,
      refreshTenant: loadTenant,
      isSuperAdmin, isEnterpriseAdmin, isRegularUser
    }}>
      {children}
    </TenantContext.Provider>
  );
}

// ━━━ 4. Hook personnalisé pour consommer le Context ━━━
export function useTenant() {
  return useContext(TenantContext);
}

5.3 — ThemeContext : mode sombre/clair

// context/ThemeContext.tsx
import { createContext, useContext, useState } from 'react';

const Themes = {
  light: {
    bg: '#F5F5F7', card: '#FFFFFF', text: '#1C1C1E',
    subText: '#8E8E93', primary: '#007AFF', border: '#D1D1D6'
  },
  dark: {
    bg: '#121212', card: '#1E1E1E', text: '#FFFFFF',
    subText: '#A1A1A1', primary: '#0A84FF', border: '#38383A'
  }
};

const ThemeContext = createContext({
  theme: Themes.dark,
  isDark: true,
  toggleTheme: () => {}
});

export function ThemeProvider({ children }) {
  const [isDark, setIsDark] = useState(true);  // Mode sombre par défaut

  return (
    <ThemeContext.Provider value={{
      theme: isDark ? Themes.dark : Themes.light,
      isDark,
      toggleTheme: () => setIsDark(prev => !prev)
    }}>
      {children}
    </ThemeContext.Provider>
  );
}

export const useTheme = () => useContext(ThemeContext);

// Usage dans n'importe quelle page :
function MaPage() {
  const { theme, isDark, toggleTheme } = useTheme();

  return (
    <View style={{ backgroundColor: theme.bg }}>
      <Text style={{ color: theme.text }}>Bonjour</Text>
      <TouchableOpacity onPress={toggleTheme}>
        <Text>{isDark ? '☀️ Clair' : '🌙 Sombre'}</Text>
      </TouchableOpacity>
    </View>
  );
}
