Chapitre 13Signatures numériques

Les reçus de vente dans SenMoto intègrent les signatures du vendeur et du client. Ces signatures sont capturées via un canvas de dessin, converties en base64, et stockées dans la base de données avec le reçu.

13.1 — react-native-signature-canvas

// app/recu.tsx — Capture de signature
import SignatureCanvas from 'react-native-signature-canvas';
import { useRef } from 'react';

function SignatureCapture({
  onSignature
}: { onSignature: (sig: string) => void }) {
  const signRef = useRef<SignatureCanvas>(null);

  return (
    <SignatureCanvas
      ref={signRef}
      onOK={(signature) => {
        // signature = "data:image/png;base64,iVBORw0KGgo..."
        onSignature(signature);
      }}
      onEmpty={() => {
        Alert.alert('Erreur', 'Signature vide');
      }}
      descriptionText="Signez ici"
      clearText="Effacer"
      confirmText="Valider"
      webStyle={`.m-signature-pad { background: #fff; border: 2px solid #ccc; }
                 .m-signature-pad--footer .button { background: #0A84FF; }`}
      style={{ width: 340, height: 200 }}
      backgroundColor="white"
      penColor="#000"
    />
  );
}
📌 SignatureCanvas utilise une WebView Comme MapPickerModal, react-native-signature-canvas utilise une WebView avec un canvas HTML5 en dessous. La signature PNG est retournée via postMessage. C'est le même pattern bridge que la carte !

Chapitre 14Audit Log — Journal d'activité

Un audit log enregistre chaque action importante dans l'application : qui a fait quoi, quand, sur quelle donnée. C'est indispensable pour la traçabilité et la conformité.

14.1 — La table audit_logs

-- Structure de la table audit_logs
CREATE TABLE audit_logs (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  enterprise_id UUID REFERENCES enterprises(id),
  user_id UUID REFERENCES auth.users(id),
  user_name VARCHAR(255),          -- Nom lisible (pas juste UUID)
  action VARCHAR(50),               -- 'CREATE', 'UPDATE', 'DELETE', ...
  entity_type VARCHAR(100),         -- 'moto', 'vente', 'user', ...
  entity_id UUID,                   -- ID de l'entité modifiée
  entity_name VARCHAR(255),         -- Nom lisible de l'entité
  details JSONB,                    -- Détails supplémentaires (champs modifiés)
  created_at TIMESTAMPTZ DEFAULT NOW()
);

14.2 — lib/auditLog.ts

// lib/auditLog.ts — Système d'audit complet
import { supabase } from './supabase';

export type AuditAction =
  | 'CREATE' | 'UPDATE' | 'DELETE'
  | 'UPLOAD' | 'DOWNLOAD'
  | 'LOGIN' | 'LOGOUT'
  | 'APPROVE' | 'DEACTIVATE';

export type EntityType =
  | 'moto' | 'vente' | 'user'
  | 'rendezvous' | 'document'
  | 'registre' | 'decharge' | 'recu'
  | 'session';

// Labels lisibles pour l'interface
export const ACTION_LABELS: Record<AuditAction, string> = {
  CREATE: 'Création',
  UPDATE: 'Modification',
  DELETE: 'Suppression',
  UPLOAD: 'Upload',
  DOWNLOAD: 'Téléchargement',
  LOGIN: 'Connexion',
  LOGOUT: 'Déconnexion',
  APPROVE: 'Approbation',
  DEACTIVATE: 'Désactivation',
};

export const ACTION_COLORS: Record<AuditAction, string> = {
  CREATE: '#30D158',   // Vert
  UPDATE: '#0A84FF',   // Bleu
  DELETE: '#FF453A',   // Rouge
  UPLOAD: '#5856D6',   // Violet
  DOWNLOAD: '#5856D6',
  LOGIN: '#FF9F0A',    // Orange
  LOGOUT: '#8E8E93',   // Gris
  APPROVE: '#30D158',
  DEACTIVATE: '#FF453A',
};

// Fonction principale : enregistrer une action
export async function logAction(params: {
  enterprise_id: string;
  action: AuditAction;
  entity_type: EntityType;
  entity_id?: string;
  entity_name?: string;
  details?: Record<string, any>;
}): Promise<void> {
  try {
    const { data: { session } } = await supabase.auth.getSession();
    if (!session) return;

    await supabase.from('audit_logs').insert({
      enterprise_id: params.enterprise_id,
      user_id: session.user.id,
      user_name: session.user.email,  // Ou récupérer depuis profile
      action: params.action,
      entity_type: params.entity_type,
      entity_id: params.entity_id ?? null,
      entity_name: params.entity_name ?? null,
      details: params.details ?? null,
    });
  } catch (error) {
    // Ne jamais faire crasher l'app à cause d'un log raté
    console.warn('logAction failed:', error);
  }
}

// Afficher les logs avec couleurs et icônes
function LogItem({ log }: { log: AuditLog }) {
  const color = ACTION_COLORS[log.action as AuditAction] ?? '#888';
  const label = ACTION_LABELS[log.action as AuditAction] ?? log.action;

  return (
    <View style={styles.logItem}>
      {/* Badge coloré par type d'action */}
      <View style={[styles.badge, { backgroundColor: color + '22' }]}>
        <Text style={[styles.badgeText, { color }]}>{label}</Text>
      </View>

      <Text style={styles.entityName}>
        {log.entity_type}: {log.entity_name}
      </Text>

      <Text style={styles.userName}>
        Par {log.user_name}
      </Text>

      <Text style={styles.date}>
        {new Date(log.created_at).toLocaleString('fr-FR')}
      </Text>

      {/* Détails JSON si présents */}

        <Text style={styles.details}>
          {Object.entries(log.details)
            .map(([k, v]) => `${k}: ${v}`)
            .join(' • ')}
        </Text>
      )}
    </View>
  );
}

Chapitre 15Sécurité et Permissions

SenMoto gère plusieurs couches de sécurité : stockage sécurisé des tokens, authentification biométrique, et permissions granulaires par utilisateur dans les menus.

15.1 — expo-secure-store : stockage sécurisé

Les données sensibles (PIN, tokens) ne doivent jamais être dans AsyncStorage (non chiffré). expo-secure-store utilise le Keychain (iOS) et le Keystore (Android), des stockages chiffrés fournis par l'OS. 

import * as SecureStore from 'expo-secure-store';

// Sauvegarder un PIN
await SecureStore.setItemAsync('user_pin', '1234');

// Lire le PIN
const pin = await SecureStore.getItemAsync('user_pin');

// Supprimer le PIN
await SecureStore.deleteItemAsync('user_pin');

// Exemple dans SenMoto : sauvegarder l'userId pour biométrie
const saveUserId = async (userId: string) => {
  await SecureStore.setItemAsync('enterprise_user_id', userId);
};
⚠️ Limites de SecureStore Taille maximale : 2048 octets par valeur. Pour stocker de grandes données, utiliser expo-file-system avec un fichier chiffré, ou stocker seulement une référence (ID) dans SecureStore.

15.2 — expo-local-authentication : biométrie

// app/home.tsx — Déverrouillage par biométrie ou PIN
import * as LocalAuth from 'expo-local-authentication';

const checkBiometric = async (): Promise<boolean> => {
  // Vérifier si le hardware est disponible
  const available = await LocalAuth.hasHardwareAsync();
  if (!available) return false;

  // Vérifier si des empreintes sont enregistrées
  const enrolled = await LocalAuth.isEnrolledAsync();
  if (!enrolled) return false;

  // Demander authentification biométrique
  const result = await LocalAuth.authenticateAsync({
    promptMessage: 'Authentifiez-vous pour accéder à SenMoto',
    fallbackLabel: 'Utiliser le PIN',
    disableDeviceFallback: false,  // Permettre PIN si bio échoue
  });

  return result.success;
};

// Workflow de déverrouillage dans home.tsx
useEffect(() => {
  const checkAuth = async () => {
    const storedPin = await SecureStore.getItemAsync('user_pin');

    if (!storedPin) {
      setUnlocked(true);  // Pas de PIN configuré → accès direct
      return;
    }

    // Essayer biométrie d'abord
    const biometricSuccess = await checkBiometric();
    if (biometricSuccess) {
      setUnlocked(true);
    } else {
      // Afficher modal PIN
      setShowPinModal(true);
    }
  };

  checkAuth();
}, []);

15.3 — Permissions menu par utilisateur

SenMoto permet à l'admin de contrôler finement ce que chaque utilisateur peut faire dans le menu hamburger. Chaque item de menu a une clé (menu_key). 

// Table user_menu_permissions
-- enterprise_id + user_id + menu_key → is_enabled

// Clés disponibles dans HamburgerMenu.tsx
const MENU_KEYS = {
  'fichier.nouveau_dossier': 'Nouveau dossier',
  'fichier.importer': 'Importer un fichier',
  'fichier.photo': 'Prendre une photo',
  'gestion.motos': 'Gérer les motos',
  'gestion.ventes': 'Effectuer une vente',
  'gestion.rendezvous': 'Rendez-vous',
};

// Charger les permissions d'un user (admin/user_permissions.tsx)
const { data: perms } = await supabase
  .from('user_menu_permissions')
  .select('menu_key, is_enabled')
  .eq('enterprise_id', enterpriseId)
  .eq('user_id', targetUserId);

// Convertir en Set pour accès O(1)
const permittedKeys = new Set(
  perms?.filter(p => p.is_enabled).map(p => p.menu_key) ?? []
);

// Dans HamburgerMenu.tsx : afficher un item seulement si permis
{(!permittedKeys || permittedKeys.has('gestion.motos')) && (
  <TouchableOpacity onPress={() => router.push('/motos')}>
    <Text>🏍️ Gérer les motos</Text>
  </TouchableOpacity>
)}

Chapitre 16Build & Déploiement avec EAS

EAS (Expo Application Services) permet de compiler et distribuer l'app sans avoir besoin d'un Mac pour iOS ou d'Android Studio. Tout se passe dans le cloud.

16.1 — Les 3 profils de build (eas.json)

// eas.json du projet SenMoto annoté
{
  "cli": {
    "version": ">= 16.28.0",
    // Version de l'app gérée côté serveur EAS (pas dans package.json)
    "appVersionSource": "remote"
  },

  "build": {
    // ━━━ DEVELOPMENT : pour tester sur un vrai appareil ━━━
    "development": {
      "developmentClient": true,   // Dev build (pas Expo Go)
      "distribution": "internal"  // Pas dans les stores
    },

    // ━━━ PREVIEW : APK pour tests internes ━━━
    "preview": {
      "distribution": "internal",
      "android": {
        "buildType": "apk"         // APK (Android Package) - installable directement
      }
    },

    // ━━━ PRODUCTION : pour les stores ━━━
    "production": {
      "autoIncrement": true       // Auto-incrémenter le numéro de version
    }
  },

  "submit": {
    "production": {}
  }
}

16.2 — Commandes EAS essentielles

# Installer EAS CLI
npm install -g eas-cli

# Se connecter à son compte Expo
eas login

# Configurer le projet (première fois)
eas build:configure

# Build APK Android (pour tester) - prend ~10 minutes
eas build --platform android --profile preview

# Build iOS (requiert compte Apple Developer)
eas build --platform ios --profile production

# Build les deux plateformes en une commande
eas build --platform all --profile production

# Voir les builds en cours
eas build:list

# Soumettre sur les stores
eas submit --platform android
eas submit --platform ios

# Publier une mise à jour OTA (Over-The-Air) sans re-build
eas update --branch production --message "Fix bug notification"

16.3 — EAS Secrets : variables sensibles

Le fichier google-services.json contient des clés Firebase secrètes. Il ne doit jamais être dans Git. EAS Secrets le gère de façon sécurisée. 

# Envoyer google-services.json comme secret EAS
eas secret:create \
  --scope project \
  --name GOOGLE_SERVICES_JSON \
  --type file \
  --value ./google-services.json

# Dans app.config.js : lire le secret ou fallback local
googleServicesFile: process.env.GOOGLE_SERVICES_JSON
  ?? "./google-services.json"
// EAS injecte la variable d'environnement lors du build cloud
// En local : fallback vers le fichier local

# Lister les secrets
eas secret:list

16.4 — OTA Updates : mises à jour sans store

EAS Update permet de pousser des corrections de bugs sans passer par la validation des stores (qui peut prendre 1-3 jours). Seul le code JS change, pas le code natif. 

# Publier une mise à jour d'urgence
eas update --branch production --message "Correction calcul prix"

# L'app télécharge automatiquement la mise à jour au prochain lancement

// Dans app.config.js : configurer les updates
"updates": {
  "url": "https://u.expo.dev/votre-project-id"
},
"runtimeVersion": {
  "policy": "appVersion"  // Compatibilité par version app
}

Chapitre 17Patterns avancés du projet

Ce chapitre couvre des patterns de code utilisés dans SenMoto qui font la différence entre une app qui "marche" et une app de production robuste.

17.1 — Pagination et chargement infini

// app/(tabs)/index.tsx — Pagination du feed motos
const PAGE_SIZE = 10;
const [page, setPage] = useState(0);
const [motos, setMotos] = useState<FeedMoto[]>([]);
const [hasMore, setHasMore] = useState(true);
const [loadingMore, setLoadingMore] = useState(false);

const fetchMotos = async (pageNum: number) => {
  if (loadingMore) return;
  setLoadingMore(true);

  const from = pageNum * PAGE_SIZE;
  const to = from + PAGE_SIZE - 1;

  const { data } = await supabase
    .from('motos')
    .select('...')
    .eq('statut', 'disponible')
    .range(from, to);          // Pagination côté serveur

  if (data) {
    if (pageNum === 0) {
      setMotos(data);          // Première page : remplacer
    } else {
      setMotos(prev => [...prev, ...data]);  // Suite : ajouter
    }
    setHasMore(data.length === PAGE_SIZE);  // Plus de données?
  }

  setLoadingMore(false);
};

// Dans la FlatList
<FlatList
  data={motos}
  onEndReached={() => {
    if (hasMore && !loadingMore) {
      const nextPage = page + 1;
      setPage(nextPage);
      fetchMotos(nextPage);
    }
  }}
  onEndReachedThreshold={0.3}
  ListFooterComponent={
    loadingMore ? <ActivityIndicator /> : null
  }
/>

17.2 — Rafraîchissement (Pull to refresh)

const [refreshing, setRefreshing] = useState(false);

const handleRefresh = async () => {

17.4 — Gestion d'erreurs robuste

// Pattern try/catch/finally systématique dans SenMoto
const safeAction = async () => {
  setLoading(true);
  try {
    const result = await riskyOperation();
    setData(result);
  } catch (error: any) {
    // Messages d'erreur utilisateur-friendly
    const message = error?.message ?? 'Une erreur est survenue';
    Alert.alert('Erreur', message);
    console.error('safeAction error:', error);
  } finally {
    setLoading(false);  // TOUJOURS s'exécute (succès ou échec)
  }
};

// Validation avant soumission
const validateForm = (): string | null => {
  if (!formData.enterpriseName.trim()) return 'Nom requis';
  if (!formData.adminEmail.includes('@')) return 'Email invalide';
  if (formData.adminPassword.length < 6) return 'Mot de passe trop court';
  if (formData.adminPassword !== formData.adminPasswordConfirm)
    return 'Mots de passe différents';
  return null;  // null = tout est OK
};

const handleSubmit = async () => {
  const error = validateForm();
  if (error) {
    Alert.alert('Erreur de saisie', error);
    return;
  }
  // ... continuer
};

18.2 — Les pièges à éviter

  • Ne jamais mettre de données sensibles dans AsyncStorage → utiliser expo-secure-store
  • Ne jamais committer google-services.json ou les clés API dans Git → utiliser EAS Secrets
  • Ne pas appeler setState sur un composant démonté → vérifier isMounted ou annuler via AbortController
  • FlatList pour les longues listes, ScrollView pour le contenu fixe
  • Toujours utiliser useNativeDriver: true dans les animations quand possible
  • Ne pas inclure des URLs de debug (localhost) dans les builds de production
  • signUp() connecte automatiquement le nouvel utilisateur → sauvegarder/restaurer session si nécessaire
  • Les images base64 gonflent la taille de la base de données → envisager Supabase Storage pour les grands projets
  • useEffect avec async : ne pas retourner la Promise, créer une fonction interne

18.3 — Checklist d'une app de production

  • Variables d'environnement dans app.config.js extra (pas en dur dans le code)
  • EAS Secrets pour les fichiers sensibles (google-services.json)
  • Row Level Security activée sur toutes les tables Supabase
  • Validation des données avant envoi au backend
  • Messages d'erreur clairs pour l'utilisateur
  • Gestion du loading state sur toutes les opérations async
  • SafeAreaView sur toutes les pages (notches iOS)
  • KeyboardAvoidingView sur les formulaires
  • Audit log sur toutes les actions importantes
  • Permissions demandées au bon moment (avant d'en avoir besoin)
  • Test sur vrai appareil Android ET iOS (pas seulement simulateur)
  • Gestion hors-ligne (au moins afficher un message)
  • Bundle identifier unique (App Store) et package unique (Play Store)
  • Version incrémentale avant chaque build de production
  • OTA Update configuré pour les hotfixes rapides

18.6 — Comprendre le cycle de vie

// Cycle de vie d'un composant React Native

function MonComposant() {
  // 1. MONTAGE (une seule fois)
  useEffect(() => {
    console.log('Composant monté (comme componentDidMount)');

    // 3. DÉMONTAGE : retourner une fonction de nettoyage
    return () => {
      console.log('Composant démonté (comme componentWillUnmount)');
      // Annuler subscriptions, timers, etc.
    };
  }, []);  // [] = une seule fois

  // 2. MISE À JOUR (à chaque changement de dépendances)
  useEffect(() => {
    console.log('userId a changé, rechargement...');
    loadUserData(userId);
  }, [userId]);  // Exécute quand userId change

  // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  // Cycle de vie Expo Router (écrans)
  // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  import { useFocusEffect } from 'expo-router';

  // Exécute CHAQUE FOIS que l'écran devient visible
  useFocusEffect(
    useCallback(() => {
      console.log('Écran en focus → recharger les données');
      loadData();

      return () => {
        console.log('Écran perd le focus');
      };
    }, [])
  );
}

18.7 — Conseils finaux du développeur SenMoto

💡 Conseil 1 : Commence par le design, pas le code Dessine les écrans sur papier d'abord. Chaque écran = une page dans app/. Identifie quelles données sont partagées entre écrans → ce qui va dans un Context.
💡 Conseil 2 : Un State, une source de vérité Ne stocke jamais la même donnée à deux endroits. Si tu as moto en state et motoId en state, tu auras des désynchronisations. Choisis l'un des deux et dérive l'autre.
💡 Conseil 3 : Test sur vrai appareil dès le début Le simulateur iOS/Android ment souvent. Les permissions, les notifications, la caméra, le GPS — tout se comporte différemment sur un vrai téléphone. Branche-le dès le premier jour.
💡 Conseil 4 : Supabase > backend custom pour 90% des apps Auth, base de données, RLS, stockage, fonctions edge — Supabase couvre tout. Tu peux construire une app complète en production sans écrire une seule ligne de backend.
💡 Conseil 5 : Audit log depuis le jour 1 Ajouter un audit log rétroactivement est douloureux. Commence avec lib/auditLog.ts dès le début et appelle logAction() à chaque opération importante.
💡 Conseil 6 : EAS Build résout 99% des problèmes de compilation Si tu n'arrives pas à compiler localement (erreurs Gradle, Xcode, etc.), utilise eas build --profile preview. L'environnement cloud est propre et cohérent.
